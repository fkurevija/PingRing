## 📡 Mesh & Connectivity
- **Live-key-gated BLE presence**: signed V5 advertisements update proximity only after a fresh registered-key nonce response over the member's Nearby link. Proof lasts ten seconds and renews on demand; captured advertisements cannot renew it. This proves key control, not physical distance, and does not replace UWB ranging.
- **One-tap hosting**, no server registration. UWB can be enabled or disabled; Nearby Connections selects its transport, with no app-level Wi-Fi Direct selector.
- **Connection recovery prompt** for guests after the authenticated host link is unavailable for the configured interval (enabled by default at 2 minutes; configurable from 1–10 minutes in App Settings). Choose **Leave PingRing**, snooze for 2 minutes, or silence prompts for the current Ring. The prompt appears only while the radar is foregrounded and does not claim whether the host is out of range or ended the Ring while disconnected.
- **Admission control**: the Host can stop accepting members at creation or mid-event; authenticated Nearby requests are rejected and the Radar's QR button hides until re-enabled. **Discoverable** lists a public event locator on nearby phones' join screens. **Approve Each Join** holds QR-secret joins for the host; typed-code joins always require approval. Nearby's shared digits must be compared on both phones before the connection is accepted. Unanswered requests expire after two minutes.
- **Bounded capacity**: max **8 participants** (1 Host + 7 Guests), enforced by the Host (`8/8 - Full`). This bounds the amount of connection, message and ranging work; it is not a measured performance guarantee.
- **Bounded peer relay mesh**: admitted members connect over Nearby `P2P_CLUSTER`; the host remains the only admission authority, and new members must reach it directly. Signed-origin messages use duplicate suppression, a seven-hop limit, and a bounded memory-only queue that replays when links return. Signed five-second presence heartbeats can show a remote member without inventing RSSI, distance, or direction.
- **Confirmed graceful departures**: when a guest leaves while connected, an authenticated notice reaches the host, which relays it to the group. A lost link or crashed app cannot send that notice; silence still means *unreachable*, not confirmed gone.
- **Current ranging sources**: fresh UWB provides distance and bearing; compatible Wi-Fi Aware phones can supply focused phone-to-phone RTT distance without venue infrastructure. Optional **Share GPS location**, enabled only by the host, shares coordinates rounded to approximately 10 m every ten seconds and shows coordinate-derived distance with uncertainty. Neither RTT nor GPS draws a directional needle; GPS never triggers close-range haptics. Signed BLE RSSI remains the local proximity fallback on capable controllers. Radio delivery and accuracy remain [unverified on hardware](roadmap.md#unverified).
- **Automatic fallback** from sub-metre UWB to signed BLE RSSI proximity when UWB is unsupported or unavailable and the Bluetooth controller supports extended advertising. The RSSI path is smoothed over a rolling **2-second window** — the mean is taken in dBm and the distance curve applied once to the result, so one reflected or dropped advert cannot move the readout. A time window rather than a per-sample average, because the advertising rate varies by peer and the app only ever sees the reports that arrive. On unsupported hardware, RSSI proximity fails closed rather than accepting V4 group-authenticated packets.

## 👤 Identity & Join
- **Custom usernames**, saved locally via DataStore and pre-filled on future sessions. Names are enforced unique within a session, with an alert on collision.
- **Join via QR** (ML Kit, on the Host's on-screen code) or a **6-character PingRing Code** (`e.g. AB12CD`). Code fields force ALL CAPS, usernames use Word Capitalization. The Radar's QR button re-opens the code mid-event for latecomers.
- **Invite secret stays in the QR**: each event gets a random 256-bit secret. The six-character code is only a public locator; code-only joins require host approval. BLE never carries the secret.
- **Join verification**: both devices compare Nearby's shared digits before accepting. Code-only joins wait for host approval; unanswered requests expire after two minutes and are cleaned up so the guest can retry.

## 🚨 Beacons & Chat
- **Intent presets**: ✨ Found Something, 📍 Regroup Here, ⚠️ Caution, 🚨 Emergency, ⚡ Custom — with 5 colour palettes (Crimson, Amber, Emerald, Cyan, Purple) and 5 vibration rhythms (SOS/Urgent, Rapid Alert, Steady Pulse, Gentle Pulse, No Vibration). Beacons illuminate radar rings, peer pins and wave animations on receivers.
- **Quick Beacon** (`⚡`): set a configuration with **Set as Quick Beacon** in the beacon screen and the radar's Quick Beacon button sends that exact message, colour and rhythm in a single tap — no screen in between. With none set yet, the tap says so in a toast and opens the beacon screen.
- **Offline group chat** with sender-labelled bubbles. Each member gets four randomized bubble-colour presets per PingRing, stable while reopening settings and independently chosen for each member, plus a custom hue picker. Selections save immediately and can be undone once. The chosen colour travels with new messages, while messages from older builds retain the theme colour. The chat window floats over the radar while typing, then returns to its docked position.
- **Beacons live in the chat transcript**: a beacon that is *running* is pinned to the newest end, where a current thing belongs and the eye already is. When it ends it moves back to where it was raised, ordered by timestamp among the messages around it. Nothing about how a beacon looks changes either way — same entry, same styling, just a different place in the conversation. A peer that disconnects mid-beacon has it ended rather than dropped, since it happened.
- **Host-preserved history**: the Host keeps the transcript for the life of the PingRing and replays it to peers who join or reconnect.
- **Configurable notifications**: toggle chat push, sound and vibration device-wide in **App Settings → Notifications**, and chat push per-PingRing in **PingRing Settings**. Notifications are suppressed while you are already watching the radar with the screen on and unlocked; the device can still vibrate or sound.

## 🧭 Radar, Theming & Hardware Adaptation
- **Sensor-fusion tracking**: rotation-vector, magnetometer and accelerometer orient peer vectors into world space while a non-blocking UWB session supplies sub-metre distance, azimuth and elevation for the focused member.
- **UWB cross-checked against BLE, and marked when obstructed.** UWB's dominant error in a crowd is not noise but **obstruction**: a body between two phones blocks the direct first path, the round trip is measured off a reflection, and the distance reads *too long* — often by metres, always in the same direction. BLE signal strength degrades under that same body, and it is an independent measurement of the same geometry, which is what makes it a usable check. So the RSSI estimate is now kept alive while ranging (it used to be discarded the moment a UWB fix arrived, making the two mutually exclusive) and the radar reports **Cross-checked**, **Someone may be in the way**, or **Distance estimate only** when there is only one source. This costs nothing extra — the BLE adverts are already arriving for discovery — and it matters most at exactly the kind of event the app is for.
- **Proximity haptics** under 2 m; **stale peers normally expire** from the radar after 15 s, while the focused peer may remain during its retained UWB window. The RSSI distance is the mean of a rolling 2-second window in dBm, with one window per peer, so a single reflected or dropped advert cannot move the readout and eight members cannot average into each other. It is a window in *time* rather than a count of samples on purpose: a sample-weighted average would smooth differently depending on how often a peer happens to advertise, which the app cannot see.
- **Weak BLE signal warning** for the tracked member, or a group summary when other members are fading. It requires a smoothed signal at or below -85 dBm for 1.5 s and clears above -80 dBm to avoid flicker. It warns that BLE proximity may disappear; it is not a measurement of Nearby transport health.
- **Who is tracked, and who decides**: a **Tracking** dropdown names whoever the radar and the single UWB session are following, and changes it — the per-row buttons can also set it, and tapping the tracked row again returns to the automatic choice. With nothing chosen, a guest follows the **host** and the host follows **whoever joined first** — role-based rather than nearest, because "nearest" changes underneath the user as people walk. Every member advertises its arrival time, so "first" means first rather than first-heard: a member who wanders in late and stands nearest is not mistaken for the one who has been there since the start. Turning on **Track Host** locks every guest to the host and disables the picker for them, visibly rather than by hiding it, so the radar is never pointed at somebody with no way to find out why. The host is never locked: the policy asks *members* to follow it, it does not constrain the host. Everyone still *receives* every message regardless of who is tracked.
- **Directional radar**: a needle points at the tracked member and a lit arc on the ring widens as they approach — a sliver when far, the whole ring within arm's reach (1.5 m). Width is spaced logarithmically, so each doubling of distance gets an equal share of the arc. With no UWB bearing the ring stays plain - signal strength only tints it - rather than inventing a direction.
- **Opt-in screen-reader radar summary**: when enabled in **App Settings → Accessibility**, the radar Canvas exposes the tracked member, distance or signal state, direction when known, and any active beacon as one spoken description. Accessibility features are off by default.
- **UWB sessions survive a transport drop**: if a member walks out of transport range while still being tracked, the ranging session stays open for up to 45 s, shortened to 20 s when radio load is high. Ending or leaving the ring discards every retained address.
- **Last known UWB direction**: after 2 s without a fresh UWB measurement, the radar freezes the last world-space bearing and labels it with its age for up to two minutes. It does not infer a direction from BLE RSSI; a BLE-only peer has no directional last-known marker. A fresh BLE sighting or UWB fix clears the marker.
- **Theming**: a fixed violet brand palette applied throughout, honouring the system's light/dark setting, an adaptive violet-and-white radar icon, and a monochrome `ic_launcher_monochrome.xml` for Android 13+ launchers. **Material You dynamic colour is deliberately not used** — see [Known limitations](roadmap.md#known-limitations).
- **Localized interface** in English, Croatian, Spanish, French, Canadian French, German, and Russian. Android 13 and newer can select PingRing's language independently in the system app-language settings; earlier Android versions follow the device language.
- **Device-aware permissions**: unsupported hardware (`FEATURE_BLUETOOTH`, `FEATURE_WIFI`, `FEATURE_LOCATION`, camera, UWB, vibrator) skips its permission prompt, and its UI is disabled with an explanatory label instead of an ungrantable dialog.
